## 2. Source Document Content

### Core Governance Doctrine
- Agents remain subordinate to governance systems
- No agent may bypass rollback or approval mechanisms
- Production safety overrides automation convenience

### Agent Classes (Functional Taxonomy)
| Class | Description |
|---|---|
| **Observer** | Read-only state retrieval |
| **Analyst** | Summarization and recommendation generation |
| **Operator** | Bounded workflow actions |
| **Executor** | Approved runtime execution |
| **Governor** | Deployment governance authority |

### Execution Constraints
- All execution requires scoped permissions
- All actions require observability and logging
- Long-running execution loops require timeout policies

### Approval Policies
- Irreversible actions require human approval
- Production deployments require governance review
- Financial and outbound actions remain restricted

### Kill Switch Requirements
- All runtime systems require termination capability
- Governance systems must override active automation

### Incident Handling
- All failed execution attempts require incident generation
- Repeated failures require escalation review

### Definition of Done
- All agents operate within deterministic governance boundaries
- No uncontrolled autonomy exists in production
